# Grilling 互動提問

適用於 `grilling`、`grill-me` 與 `grill-with-docs`：

## 訪談前蒐集脈絡

- 先判斷所需背景事實；repo 或可靠外部來源可查明的事項自行調查，不交使用者回答。
- 主 agent 拆分範圍，平行派至少 2 個 subagent，通常依下表分 3～4 路；按獨立領域增員或合併角色。每路提供原始需求、文件指標、具體問題與預期證據，不泛泛探索。

| 調查角色 | 必須查明的內容 |
| --- | --- |
| Repo 現況 | 實際入口、呼叫流程、資料與測試；區分已實作、只有文件及尚未驗證的行為 |
| 歷史脈絡 | 相關 specs、tickets、ADR 與必要的提交紀錄；過往取捨、未完成事項、曾排除的方案及原因 |
| 使用情境與影響 | 現有操作流程、使用角色、上下游影響、例外情境，以及需求與既有行為的差異 |
| 外部方案與技術限制 | 官方文件、原始碼、相關工具及公開案例；替代方案、版本相容性、宿主限制與可驗證方式 |

- Subagent 只查證與建議，使用下方調查契約，不套用 `subagent.md`。主 agent 彙整後向使用者確認決策。
- 依 [issue-tracker.md](issue-tracker.md) 找相關 specs／tickets，含已完成項目的描述與決策；必要時對照程式／提交，不預設歷史方案仍適用。
- 技術選型、第三方整合、架構取捨或可借鏡流程須派外部調查比較，不只沿用 repo 思路。優先官方文件、原始碼與一手來源，記錄 URL、版本／revision、查證日期；案例僅支持已證實範圍。無實質幫助時說明原因，聚焦 repo。
- **每輪提問門檻**：所有調查（含追加）均已回報，主 agent 已交叉彙整 repo、歷史規格與外部方案。失敗／受阻先重試或主 agent 接手；未回報不算完成。等待時可獨立查證或報進度，不開始提問。
- 矛盾與證據缺口先針對性補查，再建立決策樹，只問需使用者決策的事項；調查限於會影響需求／方案的問題。

## 調查回報契約

每個調查 subagent 必須回傳：

1. **調查範圍與結論**：回答被指派的問題，區分已驗證事實、來源宣稱與推論。
2. **證據與來源**：本地檔案路徑、行號、測試或提交；外部來源附 URL、版本與查證日期。文件宣稱與實際程式行為不同時，兩者並列。
3. **需求差異與衝突**：目前行為、歷史決策、使用者目標及外部方案之間的差異，以及受影響範圍。
4. **選項與取捨**：可行選項、適用條件、優缺點、相容性、遷移成本與驗證缺口。存在實質替代方案時比較多個選項，包含沿用／調整現有架構；不為湊數加入不相關方案。
5. **未知事項與下一步查證**：列出尚未確認的假設、可行查證方法；無法取得資料時說明限制，不以推測填補。
6. **建議深入追問**：列出需使用者決定的情境、邊界與取捨，說明不同答案會如何改變需求或設計。

主 agent 依證據呈現重要方案差異與推薦理由。外部做法不是使用者需求；未驗證相容性不標為可行。

## 互動式提問

- 所有訪談、追問、補充與確認都用 `question`，不以一般文字提問。
- 依決策依賴分輪，一次問本輪所有可回答問題，收到回答才進下一輪。每輪重檢決策樹；新情境／依賴／假設先查證再問，不因已有推薦就略過替代方案與邊界。
- 每題推薦選項置首並標「（建議）」；自由回答用內建自由輸入，確實可複選才啟用多選。
- 用具體情境釐清正常流程、角色／時機、部分成功、失敗、重試、取消、修改、刪除、舊資料與上下游影響，說明選項後果。
- 確認保留行為、範圍外與可觀察驗收。單題同意不代表未問情境已達共識。

## 需求對齊完成門檻

- 依需求／決策覆蓋收尾，不以輪數、題數、人數或時間判定；影響範圍／驗收的重要未知須繼續查問。
- 逐項確認主要情境／例外、既有行為／歷史衝突、方案取捨、範圍內外與驗收已對齊；不適用者說明理由，不機械式追問。
- 未能驗證的假設列出驗證方式、通過條件、失敗時重開的決策，讓使用者確認處理方式；同意驗證不等於技術可行。
- 彙整需求、選擇理由、保留行為與未驗證事項處理方式，經 `question` 確認共識才更新領域文件。

## 訪談後更新領域文件

- 共識確認後，自動更新已解決概念與決策的領域文件，不只提出建議。
- 將已釐清的領域詞彙記入 glossary。只有決策同時具備難以逆轉、未來讀者難以理解其原因、且涉及真實取捨時，才新增 ADR。
- 不補寫未確認事項；沒有新概念或合適 ADR 時，不建空文件或無實質更新。
- `grill-with-docs` 更新後依 repo 慣例自動 commit，僅包含本次訪談的領域文件變更，排除無關及使用者未提交修改。
