# 增量驗證與證據沿用

適用於候選修正、基線同步、整合及慢驗證優化。先讀 repo scripts、CI、依賴圖與目前工具版本；沿用既有能力，不為所有專案強制引入 Nx／Turborepo 等工具。

## 三個獨立判定

1. **影響範圍選擇**：從已驗證 base 到候選 head 的完整差異，追蹤使用端、共用契約及驗證輸入，選出必要任務。優先使用 repo 已配置的 affected／依賴分析；人工判定時記錄範圍與依據，未知則擴大到受影響套件或規定完整集合，不能只看最後一次 commit。
2. **結果快取**：必要任務已有相同有效輸入的成功證據時才重用。鍵值須涵蓋 source／測試、依賴與 lockfile、設定、命令、工具／runtime 版本、平台及相關環境識別；記錄產物與原證據位置。快取輸入不完整、非 deterministic 任務、外部狀態或動態服務測試無可信狀態識別時重跑；不記錄秘密原值。
3. **審查沿用**：Reviewer 核對實際 patch、契約、依賴及上下文是否改變，再沿用仍有效的判斷。測試 cache hit 不是 review pass，SHA 或 patch-id 相近也不代表整合結果相同。

## 落地與驗證

- 需要改善慢驗證時，由 owner 在 repo 既有腳本／設定落實「變更範圍 → 任務與輸入」對應，派工附入口及適用範圍。執行順序的依賴不一定代表 affected 傳遞，須以所用工具的實際設定確認消費端覆蓋。
- Lockfile、共享設定、工具鏈、測試 harness 或影響圖變動時，重算影響並擴大必要驗證。恢復產物前確認不含錯誤的其他 worktree 絕對路徑或可變資料；cache restore 成本高於直接執行時停用該任務快取。
- 新增或修改 affected／cache 配置時，在代表性變更對照完整必要集合，確認未漏選及沒有錯誤命中；保留 repo 指定的全量／定期對照。沒有可靠證據前採原驗證範圍，不以抽樣通過代替必要驗收。
- 每項結果記錄 base／head、任務、輸入識別、環境、結果、產物與是否實跑／快取命中。快取只重用相同輸入的證據；對新版本的適用性須另有影響分析。
- 必要重驗依 `docs/agents/test-execution.md` 的輪次辨識與耗時回饋執行：歷史成功次數不是命令總配額，純 commit SHA 改變也不是重新測試或重置失敗預算的依據。已有可比耗時用於下一輪 T，結果引用固定受測版本與 run 證據，不為文件快照追逐最新 HEAD。
- 整合到 M 後以實際合併結果重新判定必要任務；runtime／E2E 依指定環境執行，最終 spec AC 與跨票驗收照常保留。
