# Agent 測試憑證配置

`.env.test` 是 Agent／測試 harness 執行真實串接驗證的憑證來源，不是應用部署契約。產品讓使用者自行設定的服務 key，由測試讀取後透過產品既有設定流程配置到本次測試帳號／Project；不因此新增應用啟動或部署必填變數。

## 已授權的 dev 設定暫用方式

本流程已獲使用者授權：Agent 為實作及驗收所需，可直接在本機將已確認 dev 工作區的 `.env` 複製成 `.env.test`，讀取並載入必要參數，無需重問相同授權。這是完整檔案複製的明確例外，不要求使用者重填已存在的 key；來源 dev `.env` 保留不動。

- 建立前確認來源與目標絕對路徑。目標不存在時可直接複製；已存在時先判定是否為本任務產生的副本。使用者既有或歸屬不明的檔案保留，優先沿用或選擇另一個本任務暫用位置並明確配置 loader，不整份覆寫。
- 先確認目標不受 Git 追蹤且 ignore 生效，再建立副本；缺 ignore 時補齊精確規則。本機檔案操作不回傳內容，秘密不進命令列參數、聊天室、diff、log、trace 或可提交產物。提交前以檔名／追蹤狀態核對，暫用檔不 stage、commit 或 push；參數化本身不代替輸出檢查。
- 複製只是取得設定，不代表來源的 endpoint、ports、資料根目錄與資源識別可直接用在測試。依本次已確認目標與隔離配置覆寫副本的環境專屬值，只向需要的程序傳入必要參數；外部目標與操作範圍仍依環境契約。
- 在既有執行表記錄來源位置、暫用檔位置、建立者及清理時點，不記值或秘密雜湊。完成依賴該檔的實作、必要驗收與重驗後，由建立者刪除本任務產生的 `.env.test` 及其暫存副本，核對檔案不存在及未被 Git 追蹤，才完成對應收尾。取消時清理；暫停續作而需保留時記錄原因與清理責任，恢復後核對，最終仍刪除。
- 清理只涵蓋本任務產生的暫用檔；使用者原有 `.env.test`、dev `.env` 及其他任務檔案不在刪除範圍。新 worktree 可依相同授權重新建立暫用檔，不能因舊副本已清理就要求使用者重新提供 key。

## 觸發與參數歸屬

| 觸發點 | 動作 |
| --- | --- |
| 執行流程前的檢查 | 依已知驗收盤點憑證及載入方式；已有授權來源時執行同步閉環，來源缺值才補空白欄位並記錄 |
| 執行中發現缺少配置 | 先區分來源缺值與同步／載入失敗；後者自主修復，真正缺值才回報主 agent 並集中請使用者補值，其餘可做工作繼續 |

使用者直接要求配置，或 worktree 建立／恢復時需傳遞憑證，也使用本指引。實作前依全部 TODO／最終驗收盤點可預見的必要憑證並集中補問，沿用環境契約的「實作前外部條件盤點」；不以找齊所有可能的 key 作為開工門檻。

`setup-testing` 的首次實作放行須先確認本次已知必要憑證；缺值期間可繼續其他環境準備，不派產品實作。下方「缺項只阻擋相關測試」適用於獨立測試及初始放行後的執行，不覆蓋此門檻。

- **Agent 測試憑證**：供測試模擬使用者配置外部服務，放在 `.env.test`；新欄位優先採 `TEST_<SERVICE>_API_KEY` 等可辨識名稱，既有命名則保留並明列測試用途。
- **產品使用者的 key**：沿用產品 UI／設定 API 管理，不將 `.env.test` 變成正式使用者的設定來源。
- **應用本身的部署設定**：依既有部署契約處理，不能因缺值就改列為測試 key；也不能把測試 key 加入部署必填 schema、正式環境模板或一般啟動流程。
- **Ports、暫存路徑、fixtures ID**：由 Agent 依隔離環境產生或取得，沿用環境設定入口，不列為使用者需申請的 key。
- **外部測試目標與操作範圍**：帳號／tenant／repository、endpoint、可建立／發布／刪除的資源由環境契約確認；與憑證分開記錄。已有登入或 token 不代表可在任意目標操作，也不能只驗證憑證就宣稱真實產品整合通過。

## 1. 盤點與建立

- 從測試、服務設定、scripts 與 CI 找出實際參數名稱、消費程序、必要條件及既有載入方式。只要求目前檢查需要的參數；lint 不因其他測試缺 key 而受阻。
- 優先使用上方已授權 dev `.env` 暫用方式或既有測試設定入口，記錄映射與實際來源；來源缺值才提供使用者填值位置及 `.env.test.example` 空值模板。目標 worktree 依下方規則取得必要欄位；monorepo 明列各命令的工作目錄與設定檔絕對來源。
- 將已確認缺少的參數以 `TEST_<SERVICE>_API_KEY=` 形式新增到本機來源與模板，實際名稱依該服務命名；補上用途及對應測試，值留空，不填假 key。不要只新增模板卻讓使用者找不到實際填值位置。
- 建立前核對 `.env.test` 是否已存在及是否被 Git 追蹤。保留使用者已有值與未知欄位，只補缺項或修改本次指定欄位；檢查 ignore 規則涵蓋秘密檔且允許 `.env.test.example`。已追蹤的秘密檔不能僅靠新增 ignore 解決，先回報並處理其追蹤狀態。

## 2. Agent 配置與使用者配置

- **Agent 配置**：依上方 dev 暫用授權，或使用者另行指定的來源與用途，直接以本機程式複製／同步並完成測試接線，不再要求使用者手動重填相同 key。只有來源確實缺值時才建立空白欄位。秘密值不輸出到對話、命令列參數或 diff。
- **讀寫與輸出分開**：秘密不可輸出不等於禁止本機程式讀取、同步或注入已授權的必要欄位。`.env.test` 是可維護的本機設定，不因測試放行或文件快照而凍結。Owner 可自主修復本票副本、loader 與程序載入，保留來源及未知欄位；共享來源由指定配置者更新。使用者明確的禁止讀寫或工具權限限制仍須遵守；agent 自加的禁令依 implement-spec「授權沿用」核實校正。
- **使用者配置**：建立模板與缺項清單，提供檔案位置、欄位名稱及設定方法，讓使用者在本機填入 `.env.test`，或在 CI 的既有 secrets 入口配置。Agent 不生成外部服務 key，也不把 dev／正式憑證自動當作測試憑證。
- 未知值保持缺項，不猜測；已存在的檔案不整份覆寫。實作前已確認的必要缺值集中取得後才放行；`implement-spec` 正式實作中發現的缺項，依「實作前確認與實作中恢復」記錄並回報，不呼叫 question 工具，只暫停受影響操作，其他無相依工作繼續。使用者完成部分配置後即可重驗並恢復相關工作。

回報配置清單須包含：欄位名、實際填寫檔案的絕對路徑、對應服務／測試、官方取得入口與步驟、所需權限及已知費用條件、值的格式與可用環境、填好後的驗證／續作方式。可查資訊由 Agent 從專案或官方來源確認；未確認者明列，不編造申請步驟。請使用者在本機填值並通知完成，不要求把 key 貼到對話。

### 已授權來源的同步閉環

配置、補值、來源更新及新 worktree 使用時，依序完成以下動作；閱讀指引、提出方案或承諾複製均不算執行：

1. **定位**：核對來源與目標的絕對路徑、必要欄位映射、實際 loader 及消費程序。從既有授權取得用途與目標；只缺部分資訊時只確認該差額。
2. **同步**：先核對秘密檔未被 Git 追蹤且受 ignore 保護。首次建立可依 dev 暫用授權複製，再透過 repo 相容的 dotenv loader 配置目標環境；既有副本同步必要欄位並保留未知欄位及 worktree 專屬值。依已確認目標選取 endpoint，不直接採用來源環境的資源設定。已有值的衝突依第 4 節處理。
3. **載入**：核對寫入後的必要欄位與消費來源相符，只回報布林結果；再依第 3 節驗證實際 runner／服務載入。直接讀取來源的入口免建立副本，但仍須完成載入驗證。
4. **驗證與續作**：完成第 5 節的最小真實驗證，記錄各階段工具結果，立即恢復受影響驗收。失敗依環境契約自主診斷；檔案未寫入、仍讀舊副本或程序未更新均屬配置未完成。

上述界線內的同步／載入修復不等待 `test.md` 先修改或提交；依環境契約「診斷與修訂」留證並在回報節點更新設定來源、映射與驗證結果。需要更換外部目標、使用未授權憑證或改動其他 owner 的共享服務時，先協調相應差額。

若先前工具輸出意外包含秘密，先修正輸出邊界、依證據保存政策處理可控制的紀錄，並提示輪替建議。使用者已明確授權使用現有憑證，且無上位政策或工具限制要求停用時，繼續以不輸出秘密的本機方式完成配置；輪替建議本身不新增批准門檻。若確有停用要求，記錄具體政策／限制來源與受影響操作。`.gitignore` 僅處理未追蹤檔的提交排除，不能代替輸出脫敏。

## 3. 接到真正執行的程序

- `.env.test` 不會因檔名而自動生效。由測試 runner／fixture 依 repo 支援的 loader 明確讀取；缺少接線時在目標 worktree 補齊，不將 dotenv 檔當成 shell script 執行，也不讓一般應用啟動預設載入此檔。
- 載入設定與校驗必要憑證分開：依實際選取的測試／fixture，在使用前才校驗該項所需欄位。共用初始化、config 載入及測試 discovery／import 不得因無關測試 key 留空而中止整套；相關真實測試記為「前置受阻」，其他無相依測試仍可執行。
- Runner 無原生「前置受阻」狀態時，以既有分組／選取入口隔離受影響測試，另記原定集合、受阻案例／驗收 ID 及原因。未執行案例不算通過，不能只看其餘集合 exit code 為零就宣稱完整驗收成功；接線阻斷無相依測試時由 owner 修復，不全數歸為等待補 key。
- 驗收使用者配置 key 的流程時，fixture 透過 UI／產品設定 API 將 key 配置到本次擁有的測試資源；驗收 UI 輸入流程就必須走 UI。其他行為可按驗收邊界用產品 API 準備。不能直接注入 server 環境而繞過正在驗收的產品配置流程。
- 在專案驗證紀錄寫明實際優先序。無既定規則時採「本次明確注入的測試設定（含 CI secrets）→ `.env.test` → 非機密預設值」；核對父程序繼承的同名變數，不能把未知的 dev 值視為明確測試注入。端點、ports、資料位置與隔離契約不符時先失敗，不能靜默 fallback。
- 依實際 loader 處理引號、空格及特殊字元，不手寫另一套不相容解析器。只向需要的測試程序傳遞必要參數；透過 UI 填 key 是測試操作，不得將 key 放進 `VITE_*`、`NEXT_PUBLIC_*` 或前端打包內容。含憑證的輸入、network 與 trace 證據須遮蔽或限制保存。
- 測試 runner 在容器內時，核對其實際取得的變數；Compose 的 `--env-file` 插值不等於容器注入。Playwright runner 能讀 key 也不代表產品已配置成功，須透過產品可觀察結果驗證；只在產品契約原本需要時才配置 server 的環境變數。
- 容器環境變數變更時，依既有 Compose 入口重建受影響的任務自有服務並保留資料；單純 `restart` 不會套用新環境變數。程序載入驗證只輸出必要欄位是否符合預期，不輸出完整 `compose config`、`inspect` 環境或秘密檔內容。

## 4. Worktree 與續作

- `.env.test` 通常不受 Git 追蹤，新 worktree 不會自動取得。主 agent 指定測試參數來源，owner 只將已授權且必要的參數載入自己的 worktree／程序；主工作區的來源檔由指定配置者維護，票級 owner 發現新缺項時回報，由主 agent／指定配置者去重並新增空白欄位，避免並行回寫共享來源。
- 可共用的測試憑證與 worktree 專屬設定分開處理：完整複製 dev `.env` 後，ports、資料根目錄、Compose 識別、Project／帳號隔離值仍由目標環境產生並配置。若憑證指向共享帳號，仍須依環境契約隔離可變資料或串行操作。
- 使用者更新來源後，主 agent 通知受影響 worktree 的 owner。各 owner 先核對實際消費來源：直接讀取主來源者免複製；使用 worktree 檔案或暫存副本者，先同步已授權且變更的憑證欄位，再重新載入測試程序。Git 合併或僅重啟 runner 不會更新未追蹤的設定副本。
- 同步只更新由指定來源管理的憑證欄位，保留 worktree 專屬 ports、路徑、資源識別及使用者修改；來源與本地修改衝突時記錄具體待決項，不整份覆寫。依前述優先序核對明確注入的環境變數，不能假設檔案更新即代表有效值已更新。
- 確認受影響測試程序已載入預期來源後，透過產品配置流程更新本次測試資源並重驗；僅在既有契約要求時重啟自有服務。以來源位置、同步／載入狀態與驗證結果留證，不輸出憑證值；仍讀到舊副本屬 owner 應修復的接線問題，不再次要求使用者提供相同 key。
- 清理依上方 dev 暫用方式與檔案所有權執行：依賴驗收完成後刪除本任務產生的 `.env.test`／暫存副本，保留使用者維護的來源檔；產品測試設定依所有權清理，不改動真實使用者的 key。記錄來源位置與更新時間，不保存秘密值或其雜湊作為證據。

## 5. 完成判定

先在實際消費程序檢查必要欄位非空、非 placeholder、格式及測試目標正確，再於既有授權與有限時限內做最小連線／權限驗證。診斷只報欄位名、來源、是否已設定與遮蔽後錯誤，不列印環境變數全集。

分別回報「檔案已配置」「程序已載入」「外部服務已驗證」；只有前兩者完成不能宣稱 key 有效。配置結果記入既有驗證紀錄：命令、消費程序、優先序、缺項、受影響測試與下一動作。配置入口有修改時，驗證缺值只阻擋相關測試、無相依測試仍可被發現並執行、有效值可載入及隔離目標不會被舊設定覆蓋。使用憑證副本的入口另驗證「更新主來源 → 同步必要欄位 → 程序重新載入」可生效，且 worktree 專屬設定保持不變；載入驗證可用非秘密測試值，不能據此宣稱真實服務授權已通過。
