# 配置測試環境參數

使用者要求配置 `.env.test`、測試缺少參數，或建立／恢復隔離環境需傳遞設定時使用。沿用專案既有 loader 與命令，讓 Agent 與使用者共用可重跑的配置入口。

## 1. 盤點與建立

- 從測試、服務設定、scripts 與 CI 找出實際參數名稱、消費程序、必要條件及既有載入方式。只要求目前檢查需要的參數；lint 不因其他測試缺 key 而受阻。
- 預設以目標專案根目錄的 `.env.test` 保存本機測試參數，以 `.env.test.example` 保存可提交的空值模板。已有同等測試設定入口時沿用並記錄映射；monorepo 明列各命令的工作目錄與設定檔絕對來源。
- 模板只列該專案實際使用的名稱、用途、哪些測試需要、格式與取得方式；key 留空，不填看似可用的假值。端口或路徑範例須標示需依隔離環境產生。
- 建立前核對 `.env.test` 是否已存在及是否被 Git 追蹤。保留使用者已有值與未知欄位，只補缺項或修改本次指定欄位；檢查 ignore 規則涵蓋秘密檔且允許 `.env.test.example`。已追蹤的秘密檔不能僅靠新增 ignore 解決，先回報並處理其追蹤狀態。

## 2. Agent 配置與使用者配置

- **Agent 配置**：直接填入已確認的測試 endpoint、專屬 ports、資料路徑及非機密預設值。使用者已指定可用的測試憑證來源時，以本機讀取／傳遞方式配置必要欄位，沿用既有授權；不把秘密值輸出到對話、命令列參數或 diff。
- **使用者配置**：建立模板與缺項清單，提供檔案位置、欄位名稱及設定方法，讓使用者在本機填入 `.env.test`，或在 CI 的既有 secrets 入口配置。Agent 不生成外部服務 key，也不把 dev／正式憑證自動當作測試憑證。
- 未知值保持缺項，不猜測；已存在的檔案不整份覆寫。`implement-spec` 中先完成其他可自主推進工作，再依集中詢問規則請使用者補缺項；使用者完成部分配置後即可重驗並恢復相關工作。

## 3. 接到真正執行的程序

- `.env.test` 不會因檔名而自動生效。核對 runner、app server、BFF／runtime、fixtures 與清理命令各自如何載入；缺少接線時，在目標 worktree 補上 repo 支援的 loader／啟動入口。不要將 dotenv 檔當成 shell script 執行。
- 在專案驗證紀錄寫明實際優先序。無既定規則時採「本次明確注入的測試設定（含 CI secrets）→ `.env.test` → 非機密預設值」；核對父程序繼承的同名變數，不能把未知的 dev 值視為明確測試注入。端點、ports、資料位置與隔離契約不符時先失敗，不能靜默 fallback。
- 依實際 loader 處理引號、空格及特殊字元，不手寫另一套不相容解析器。只向需要的程序傳遞必要參數；API key 留在伺服器端，不能放進 `VITE_*`、`NEXT_PUBLIC_*` 等瀏覽器公開設定。
- Docker Compose 的 `--env-file` 插值不等於容器收到變數；需核對 service 的 `environment`／`env_file` 與容器內有效設定。Playwright 的 runner 與 `webServer` 也要分別確認，不能以 runner 看得到 key 當作 server 已就緒。

## 4. Worktree 與續作

- `.env.test` 通常不受 Git 追蹤，新 worktree 不會自動取得。主 agent 指定測試參數來源，owner 只將已授權且必要的參數載入自己的 worktree／程序；主工作區的來源檔由指定配置者維護，票級 owner 不回寫共享來源。
- 可共用的測試憑證與 worktree 專屬設定分開處理：ports、資料根目錄、Compose 識別、Project／帳號隔離值由目標環境產生，不整份照抄來源 `.env.test`。若憑證指向共享帳號，仍須依環境契約隔離可變資料或串行操作。
- 使用者更新來源後，重新載入已變更欄位；既有服務不會自動取得新值，按歸屬重啟必要自有程序並重驗。保留目標 worktree 的專屬設定與使用者修改，來源／本地修改衝突記為具體待決項。
- 清理 run 資源不刪除使用者維護的來源 `.env.test`；本次產生的暫存憑證副本依已確認生命週期清理。記錄來源位置與更新時間，不保存秘密值或其雜湊作為證據。

## 5. 完成判定

先在實際消費程序檢查必要欄位非空、非 placeholder、格式及測試目標正確，再於既有授權與有限時限內做最小連線／權限驗證。診斷只報欄位名、來源、是否已設定與遮蔽後錯誤，不列印環境變數全集。

分別回報「檔案已配置」「程序已載入」「外部服務已驗證」；只有前兩者完成不能宣稱 key 有效。配置結果記入既有驗證紀錄：命令、消費程序、優先序、缺項、受影響測試與下一動作。配置入口有修改時，驗證缺值快速失敗、有效值可載入及隔離目標不會被舊設定覆蓋。
