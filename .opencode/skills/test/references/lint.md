# Lint 靜態檢查

## 選擇與執行

- 從 repo scripts、linter 設定與 CI 找出權威命令、適用套件及 warnings 門檻，使用鎖定版本與既有套件管理器。優先使用 repo script，不以全域工具或未固定的最新版替代。
- 開發時可依工具支援對變更範圍做快速檢查；交付仍執行受影響套件及 CI／spec 要求的範圍。核對排除規則與實際掃描檔案，避免 lint 沒掃到修改內容卻宣稱通過。
- 預設執行檢查模式。必要的 autofix 限當前授權修改範圍，先核對既有未提交變更，完成後檢閱 diff，再跑檢查；避免無關的整庫格式化。

## 問題處理

- 新增的 lint 錯誤由 owner 修正。Warnings 依 repo／CI 門檻判定並明列；既有 warnings 附基線證據，沒有基線時標來源待確認，不當成已知舊問題。
- 規則或設定缺陷先查工具版本與 repo 約定；真正需要變更規則時記錄理由及影響，依既有授權處理。不以停用規則、擴大 ignore、調高 warnings 上限或插入 suppression 來掩蓋待修問題。
- Linter 無法啟動、設定解析失敗或相依缺少屬驗證未完成；先修復入口，不只處理畫面上的程式錯誤。
- Lint 不證明執行行為或完整型別正確性；typecheck、build 及行為測試仍按驗證清單獨立執行。

完成證據包含命令、掃描範圍、exit code、errors／warnings 及處理方式；未解的必要失敗保持受阻，不標全部驗證通過。
